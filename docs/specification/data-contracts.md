## 1. What changed from TDD v1.0

The preliminary contract has been kept. Field names, types, the storage key and integer minor units are unchanged. This revision only **clarifies** things the preliminary contract left open:

| Item | TDD v1.0 | Revision 1.2 | Decision |
| --- | --- | --- | --- |
| `Transaction.category`, `Budget.category` | `"string"` | A **category ID** from the controlled list in §3 (for example `"food"`), never a display label | DEC-03, DEC-04 |
| `Transaction.description` | `"string"` | Optional. Defaults to `""`; at most 120 characters after trimming | DEC-05 |
| `Goal.targetDate` | `"string \| null"` | `"YYYY-MM-DD"` or `null` | DEC-17 |
| `Goal.name` | `"string"` | 1–60 characters after trimming | DEC-17 |
| Amount upper bound | not set | `amountMinor`, `limitMinor` and `targetAmountMinor` must be ≤ **99,999,999,999** | DEC-06 |
| `settings` defaults | not set | `{ "currency": "USD", "theme": "dark" }` | DEC-20, DEC-21 |
| Context actions | suggested list | Final signatures, plus `switchCurrency` and the read-only `storageStatus` (§11) | DEC-19, DEC-24, DEC-27 |

No `createdAt`/`updatedAt` fields are added. When two records have the same date, array order breaks the tie (BR-SORT-01, DEC-13).

## 2. Shared conventions

| Convention | Rule |
| --- | --- |
| Money | Integer **minor units** in the active currency: USD → cents (`1250` = $12.50), KHR → whole riel (`25000` = 25,000៛). Every stored amount is a positive safe integer from 1 to 99,999,999,999. Amounts carry no currency of their own; `settings.currency` gives them meaning. |
| Dates | Local calendar date string `YYYY-MM-DD`. Never create one with `toISOString()`: in Phnom Penh (UTC+7) that gives the previous day between 00:00 and 06:59. See BR-DATE-01. |
| Months | `YYYY-MM`, month `01`–`12`. The month of a date is `date.slice(0, 7)`. |
| IDs | Stable, opaque strings matching `^[A-Za-z0-9_-]{1,64}$`, unique within their collection, generated by `createId()` (§2.1). IDs are never reused or shown to users. |
| Text | Trimmed before validation and storage. React renders it as text only; `dangerouslySetInnerHTML` is prohibited (NFR-05). |
| Collections | Persisted arrays keep insertion order. New records are **appended**. Edits replace a record **in place** and keep its ID and array position. |

### 2.1 ID generation

```js
/** @returns {string} */
export function createId() {
  if (typeof crypto !== 'undefined' && typeof crypto.randomUUID === 'function') {
    return crypto.randomUUID(); // e.g. "3b241101-e2bb-4255-8caf-4136c566a962"
  }
  // crypto.randomUUID is undefined outside secure contexts, e.g. phone testing
  // over http://192.168.x.x:5173. This fallback still matches the ID pattern.
  return `${Date.now().toString(36)}-${Math.random().toString(36).slice(2, 10)}`;
}
```

## 4. Transaction

One income or expense record. Owned by WBS 1.3.1 (Narith).

| Field | Type | Required | Default | Validation (on write) | Relationships | Example |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | `string` | Yes (system) | `createId()` | ID pattern; unique among transactions | Referenced by nothing; React list key | `"t-10"` |
| `type` | `"income" \| "expense"` | Yes | Form preselects `"expense"` | One of the two values | Decides which category subset is valid | `"expense"` |
| `amountMinor` | `integer` | Yes | none | Safe integer, 1 ≤ n ≤ 99,999,999,999 (BR-MONEY-01…05) | Read in `settings.currency` | `1750` |

## 5. Budget

A monthly spending limit for one expense category. Owned by WBS 1.3.3 (Narith).

| Field | Type | Required | Default | Validation (on write) | Relationships | Example |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | `string` | Yes (system) | `createId()` | ID pattern; unique among budgets | none | `"b-01"` |
| `category` | `ExpenseCategoryId` | Yes | none | Must be an **expense** category (BR-BUD-01) | Matches `Transaction.category` for expense transactions | `"food"` |
| `month` | `string` (`YYYY-MM`) | Yes | The month selected on /budgets, shown read-only in the form and fixed on edit (BR-BUD-03) | Valid month, `2000-01` ≤ month ≤ `2099-12` (BR-DATE-04) | Matches `Transaction.date.slice(0,7)` | `"2026-11"` |
| `limitMinor` | `integer` | Yes | none | Safe integer, 1 ≤ n ≤ 99,999,999,999 | Compared with derived `spentMinor` | `5000` |

## 9. LocalStorage snapshot

| Field | Type | Required | Default | Validation (on load) | Example |
| --- | --- | --- | --- | --- | --- |
| `schemaVersion` | `1` (integer literal) | Yes | `1` | Must equal `1`; anything else makes the snapshot unreadable (BR-STO-03) | `1` |
| `transactions` | `Transaction[]` | Yes | `[]` | Must be an array; invalid items are dropped (BR-STO-04) | fixture |
| `budgets` | `Budget[]` | Yes | `[]` | Must be an array; invalid items and later duplicate `(category, month)` pairs are dropped | fixture |
| `goals` | `SavingsGoal[]` | Yes | `[]` | Must be an array; invalid goals are dropped; invalid contributions inside a valid goal are dropped | fixture |
| `settings` | `Settings` | Yes | `DEFAULT_SETTINGS` | Invalid `currency` makes the snapshot unreadable; invalid `theme` falls back to `"dark"` | `{ "currency": "USD", "theme": "dark" }` |

| Storage key | Contents | Written when |
| --- | --- | --- |
| `flowbudget:v1` | `JSON.stringify(snapshot)` (no indentation) | Hydration, then after every state change (BR-STO-01) |
| `flowbudget:v1:backup` | The raw, unparsed string found under `flowbudget:v1` | Only when a load finds unreadable or partly invalid data (BR-STO-05). One slot; each backup overwrites the last |

Unknown top-level keys are ignored on load and are not written back.

**Stored-record rules and write rules.** On load, each record is checked against its **write rules minus two time-dependent checks**: "date ≤ today" and goal-name uniqueness. Stored dates only need `2000-01-01` ≤ date ≤ `2099-12-31`. That way a clock or timezone change can never delete saved data.

 * @property {Settings} settings
 */

export const STORAGE_KEY = 'flowbudget:v1';
export const BACKUP_KEY = 'flowbudget:v1:backup';

/** @returns {FinanceSnapshot} */
export const createDefaultSnapshot = () => ({
  schemaVersion: 1,
  transactions: [],
  budgets: [],
  goals: [],

## 11. Finance Context contract (`useFinance()`)

The provider holds one `FinanceSnapshot` in `useState`, hydrated with a **lazy initializer** that calls `loadSnapshot()` (DEC-23). Pages read state and call actions; they never write to `localStorage` directly. Component-local state (form fields, filters, selected month, open modals) is not part of Context and is never persisted (TDD Rev 1.1, DEC-32).

```js
/**
 * Result of every mutating action. Actions never throw for validation problems.
 * `errors` keys are field names ("amountMinor", "category", "date", "name", ...)
 * or "_form" for record-level problems such as NOT_FOUND. Values are message
 * codes from business-rules.md §10.
 * @template T
 * @typedef {{ ok: true, value: T } | { ok: false, errors: Record<string, string> }} ActionResult
 */

/**
 * @typedef {Object} StorageStatus
 * @property {boolean} persistent                    false when localStorage is unavailable.
 * @property {LoadResult} loadResult
 * @property {number} droppedCount
 * @property {boolean} loadNoticeDismissed
 * @property {null | 'quota' | 'unavailable'} lastSaveError  Cleared by the next successful save.
 */

/**
 * @typedef {Object} FinanceContextValue
 * @property {Transaction[]} transactions
 * @property {Budget[]} budgets
 * @property {SavingsGoal[]} goals
 * @property {Settings} settings
 * @property {StorageStatus} storageStatus
 *
 * @property {(input: TransactionInput) => ActionResult<Transaction>} addTransaction
 * @property {(id: string, input: TransactionInput) => ActionResult<Transaction>} updateTransaction
 * @property {(id: string) => ActionResult<null>} deleteTransaction
 *
 * @property {(input: BudgetInput) => ActionResult<Budget>} addBudget
 * @property {(id: string, input: BudgetInput) => ActionResult<Budget>} updateBudget
 * @property {(id: string) => ActionResult<null>} deleteBudget
 *
 * @property {(input: GoalInput) => ActionResult<SavingsGoal>} addGoal
 * @property {(id: string, input: GoalInput) => ActionResult<SavingsGoal>} updateGoal   Keeps contributions.
 * @property {(id: string) => ActionResult<null>} deleteGoal                            Deletes its contributions.
 * @property {(goalId: string, input: ContributionInput) => ActionResult<SavingsContribution>} addContribution
 * @property {(goalId: string, contributionId: string) => ActionResult<null>} removeContribution
 *
 * @property {(patch: { theme: Theme }) => ActionResult<Settings>} updateSettings       Theme only.
 * @property {(currency: Currency) => ActionResult<Settings>} switchCurrency            Clears records if any exist (BR-CUR-02).
 * @property {() => ActionResult<null>} resetData                                       Factory reset (BR-CUR-04).
 * @property {() => void} dismissLoadNotice
 */
```

| Action | Validates with | Errors it can return | State change on success |
| --- | --- | --- | --- |
| `addTransaction` | `validateTransactionInput(input, { today })` | field codes | Append `{ id: createId(), ...normalized }` |
| `updateTransaction` | same | field codes, `_form: NOT_FOUND` | Replace in place; keep `id` and position |
| `deleteTransaction` | ID lookup | `_form: NOT_FOUND` | Remove |
| `addBudget` | `validateBudgetInput(input, budgets)` | field codes incl. `BUDGET_DUPLICATE` | Append |
| `updateBudget` | `validateBudgetInput(input, budgets, id)` | as above, `_form: NOT_FOUND` | Replace in place |
| `deleteBudget` | ID lookup | `_form: NOT_FOUND` | Remove; transactions untouched |
| `addGoal` | `validateGoalInput(input, goals)` | field codes incl. `GOAL_NAME_DUPLICATE` | Append `{ ...normalized, id, contributions: [] }` |
| `updateGoal` | `validateGoalInput(input, goals, id)` | as above, `_form: NOT_FOUND` | Replace name/target/targetDate; keep contributions |
| `deleteGoal` | ID lookup | `_form: NOT_FOUND` | Remove goal and its contributions |
| `addContribution` | `validateContributionInput(input, { today })` | field codes, `_form: NOT_FOUND` | Append to that goal's `contributions` |
| `removeContribution` | ID lookups | `_form: NOT_FOUND` | Remove from that goal |
| `updateSettings` | theme ∈ {light, dark} | `theme: THEME_INVALID` | Set theme |
| `switchCurrency` | currency ∈ {USD, KHR} | `currency: CURRENCY_INVALID` | See BR-CUR-02 |
| `resetData` | none | none | Replace state with `createDefaultSnapshot()` |

Every action uses the functional `setState(prev => …)` form so that back-to-back calls never lose an update. Persistence is a `useEffect` on the snapshot (BR-STO-01). `addContribution` with an unknown `goalId` returns `NOT_FOUND`.
